# NAR月次CSVを南関予想に使う

ばんえい予想（`../../ばんえい予想`）で効いている「相対評価の材料の総ざらい」と
「騎手×厩舎の母数補正つき成績」を、南関へ移植したときの実装と検証の記録。

## 何が入ったか

| ファイル | 役割 |
| --- | --- |
| `nar_history.py` | NAR公式の月次レースCSVを読み、出走・レース・騎手/厩舎成績のインデックスを作る |
| `nar_bridge.py` | `keiba_bot.py` から使うための橋渡し。既存関数と同じ形で答えを返す |
| `scripts/backtest_jockey_model.py` | 騎手評価の作り方をAUCで比較する |
| `scripts/backtest_csv_pipeline.py` | 相対評価を通信なしで丸ごと再現し、過去走の材料量を比較する |

### データの置き場所

読む先は次の順に探し、同じ月が複数あれば新しいファイルを使う。

1. 環境変数 `NAR_CSV_DIRS`（`:` 区切りで複数指定可）
2. `data/nar_csv/`
3. `cache/nar_speed_csv/monthly/*.zip`、`cache/nar_speed_csv/daily/*.zip`
   （`tools/update_nar_speed_reference.py` が落としてくるもの）
4. `../../ばんえい予想/data/`（同じ月次CSVの展開済み）

既定では**南関4場だけ**を読み込む（2021-06以降で約20万出走）。
`NAR_CSV_PLACES=all` で全場、`NAR_CSV_SINCE=2025-04-01` で期間を絞れる。

対象レースより未来のデータは使わない。同じ開催日でも、対象Rより後のレースは
騎手成績の母集団に入れない。

## ① 騎手評価（②騎手点）を2025年の静的表から当季実績へ

これまでの騎手点は `2025data/2025_騎手パワー.xlsx` の「騎手パワー」を土台にしていた。
2025年の集計なので、2026年にデビュー・移籍した騎手は引けず（対象16,552出走のうち700出走）、
調子や厩舎との相性も反映されない。

CSVからは、対象日から**遡り365日**の南関成績を母数補正（12騎乗ぶんの事前分布へ縮約）つきで作れる。

2026-04-01〜09-17の南関15,852出走（2025パワーが引けた馬のみ／同じ母集団で比較）のROC-AUC:

| 指標 | 1着AUC | 3着内AUC |
| --- | ---: | ---: |
| 現行 2025騎手パワー | 0.681 | 0.648 |
| 騎手 勝率（補正） | 0.669 | 0.641 |
| 騎手×競馬場（縮約） | 0.679 | 0.648 |
| 騎手×厩舎（縮約） | 0.691 | 0.651 |
| **場×厩舎 平均（採用）** | **0.696** | **0.658** |
| （参考）単勝人気 | 0.836 | 0.802 |

採用したのは `0.5 ×(騎手×競馬場) + 0.5 ×(騎手×厩舎)`。どちらも騎手単体の成績へ縮約して
あるので、騎乗数が薄い組み合わせでも極端な値にならない。
0〜15点への目盛りは、現行の騎手パワーと分布が揃うように合わせた（中央3点・上位1割12点）。

### 母集団の窓は「当季」ではなく「遡り365日」

ばんえいは当季（4月始まり）で足りるが、南関は年度初めの母数が薄く当たらなかった。

| 母集団 | 騎手×厩舎の1着AUC | 3着内AUC |
| --- | ---: | ---: |
| 当季（4月始まり） | 0.637 | 0.603 |
| 遡り180日 | 0.657 | 0.616 |
| **遡り365日（採用）** | **0.658** | **0.622** |
| 遡り730日 | 0.659 | 0.627 |

730日も同じくらいだが、古い成績を引きずるので365日を選んだ。

### ばんえいの「勝負気配」は南関では効かなかった

ばんえいでは乗り替わり・騎手×調教師・騎手の調子を点にしている（`jockey_intent_signals`）。
同じものを南関で作って測ると、材料そのものが弱い。

| 材料 | 1着AUC | 3着内AUC |
| --- | ---: | ---: |
| 乗り替わり（騎手×厩舎の差） | 0.503 | 0.508 |
| 騎手×厩舎の厩舎平均との差 | 0.554 | 0.543 |
| 騎手の直近30日トレンド | 0.509 | 0.515 |

ベース（場×厩舎平均）へ上乗せすると、重みを0.0002まで小さくしても前半・後半とも下がる。
**点には入れず、画面に出す根拠としてだけ残した**（`ConnectionModel.signals`）。

### 現行の「現P − 前P」加算も、当たりを下げている

いまの `score_2` は乗り替わり時に `p_base - p_prev` を足している。
CSVの騎手点で同じ式を測ると、

| 式 | 1着AUC | 3着内AUC |
| --- | ---: | ---: |
| 騎手点のみ | 0.6946 | 0.6581 |
| 騎手点 + 0.5×(現P−前P) | 0.6839 | 0.6487 |
| 騎手点 + (現P−前P)（現行式） | 0.6738 | 0.6399 |

**既定はこれまで通り加算する**（モデルの作りを黙って変えないため）。
外して試すときは `NANKAN_JOCKEY_SWITCH_DELTA=0`。

## ② 相対評価（⑤50点）の材料をCSVで総ざらい

相対評価は「同じレースを走った馬どうし」をつないで順位を作る。材料は2か所から来る。

1. 各馬の過去走（南関公式の馬柱＝**直近5走まで**）
2. その過去レースの全出走馬（物差し馬）＝レースごとに1ページずつスクレイピング

CSVが読めれば両方とも通信なしで取れ、しかも5走の上限がない。

* `fetch_race_all_horses()` … 南関16桁レースIDをCSVへ引き当て、出走全頭の
  勝ち時計との差・確定着順・人気・馬番を返す。CSVに無ければ従来通りスクレイピングへ落ちる。
* `extend_hist_with_csv()` … スクレイピング済みの5走より**古い**走りだけをCSVから足す
  （既に取れている走りは重複させない）。`NANKAN_CSV_HIST=0` で止まる。

CSVで足した走りは、コースの内外回り区分を持たないので**共通速度指数の材料には入れない**
（`from_csv` で除外）。相対評価と対戦材料にだけ使う。

画面のリンクは、CSV由来の走り（内部キー `nar://場/日付/R`）ではリンクにせず文字だけ出す
（`_safe_href`）。

### 材料を増やすと相対評価は良くなるか

`scripts/backtest_csv_pipeline.py` は、出馬表も過去走もCSVだけで組み立て、
`calculate_horse_scores` をそのまま通して答え合わせする（通信なし）。
2026-07-01〜09-10の南関291レースで、各馬の過去走を5走に切った場合と、
収録期間を総ざらいした場合を比べた。

| 材料 | 判定不能 | 相対点と着順の順位相関 | 相対1位の1着率 | 相対1位の3着内率 |
| --- | ---: | ---: | ---: | ---: |
| 5走のみ（現行相当） | 21.2% | 0.322 | 18.6% | 50.2% |
| **CSV総ざらい** | **19.4%** | **0.332** | **19.4%** | **52.6%** |

4つとも同じ向きに動いたが、291レースぶんなので効き幅（3着内で+2.4pt）は
確からしさまでは言えない。少なくとも悪くはならず、比べようのない馬が減る。

なお相対点は同点が多く（1位が平均2.8頭）、上の「1位の…率」は同点の馬で平均した値。

## 使い方

```bash
# 騎手評価の比較
python3 scripts/backtest_jockey_model.py --from 2026-04-01

# 相対評価をオフラインで再現して材料量を比較
python3 scripts/backtest_csv_pipeline.py --from 2026-07-01 --to 2026-09-10 --limit 300
```

止めたいときの環境変数:

| 変数 | 既定 | 効果 |
| --- | --- | --- |
| `NANKAN_CSV` | `1` | `0` でCSV利用を丸ごと停止（従来動作） |
| `NANKAN_CSV_HIST` | `1` | `0` で過去走の補完だけ停止 |
| `NANKAN_JOCKEY_SWITCH_DELTA` | `1` | `0` で乗り替わりの騎手P差を足さない |
| `NAR_CSV_PLACES` | 南関4場 | `all` か場名のカンマ区切り |
| `NAR_CSV_SINCE` | 全期間 | `2025-04-01` 等で読み込み期間を絞る |

## ③ 総合最下位の馬が3着内に来ない配分（7月以降・南関4場）

`scripts/backtest_bottom_allocation.py`（`--build` で材料作成、`--search` で総当たり）。
材料はCSVから作れる5つ（相対・騎手・近走・速度・前走着順）。調教・対戦表・展開は含まない。
2026-07-01〜09-17 の南関699レース（7〜8月582で選び、9月117で答え合わせ）。

| 配分（相対/騎手/近走/速度/前走） | 全体 最下位3着内 | 大井 | 川崎 | 浦和 | 船橋 | 本命3着内 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 現行相当 77/23/0/0/0 | 13.3% | 10.3% | 14.9% | 18.9% | 11.2% | 59.2% |
| **A案 30/10/10/30/20** | **7.2%** | 4.3% | 6.9% | 10.4% | 9.6% | 64.2% |
| B案 60/10/0/30/0 | 7.5% | 5.7% | 9.2% | 9.4% | 6.2% | 64.2% |
| C案 10/30/10/20/30 | 7.0% | 2.9% | 6.0% | 11.3% | 11.7% | 62.4% |
| 市場の最低人気 | 4.0% | | | | | |

* 0%にできる配分は無い。11,000通り超の総当たりで床は7%前後、9月の検証でも6〜8.5%で再現。
* 効いているのは**速度指数（30）を入れること**。相対だけだと13.6%。
* A案で「最下位と2番目の点差」が0.06以上（59%のレース）に絞ると5.4%、0.10以上（39%）で4.8%。
  大井は1〜2%まで落ちるが、浦和は10%前後から下がらない（材料が薄く同点が多い）。
* 市場の最低人気（4.0%）には、オッズを見ないかぎり届かない（ばんえいと同じ結論）。

### A案を本番に採用（2026-09-16）

`②騎手15 + ⑤相対50` の65点枠を、A案の5材料で配り直した **⑧能力点（0〜65）** に置き換えた
（`apply_ability_allocation` / `_deterministic_total`）。④調教・③盛返・⑥対戦表・⑦展開・好走パターン・
調教順位はこれまで通り上乗せする。

* 材料はレース内で0〜1に揃える：相対=点/50、騎手=点/15、近走・速度=レース内の最小〜最大
  （速度は±6秒で頭打ち）、前走=1/前走着順。欠損は0.5の中立。バックテストと同じ式。
* 近走・速度・前走着順はCSVから作る（`nar_bridge.ability_features`）。CSVが無い馬は中立。
* ②騎手・⑤相対は計算・表示ともに残す（内訳に「⑧能力NN(相対/騎手/近走/速度/前走)」を先頭に追加）。
* `NANKAN_ALLOCATION=legacy` で従来の合計式に戻る。
